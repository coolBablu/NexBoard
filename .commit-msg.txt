feat(auth): disable public sign-up; admin-only invites with company domain

Locks down account creation so only the super admin can add members,
and forces every invite to use the workspace's company email domain.

What changed
  - /signup now shows a polished "by invitation only" screen with a
    pointer to the Add member flow; the route stays so old bookmarks
    land somewhere helpful instead of 404'ing
  - POST /api/signup returns 403 once any account exists; the very
    first account still goes through (workspace bootstrap) and is
    promoted to super_admin
  - /login no longer links to /signup; copy updated to "ask your
    admin to invite you"
  - All marketing CTAs (navbar, hero, hero-cinematic, cta, pricing)
    now point at /login — there is no more "Get started" path
  - Sitemap dropped /signup
  - resolveInviteDomain() in src/lib/admin.ts derives the allowed
    domain from INVITE_EMAIL_DOMAIN env var first, then falls back
    to the super admin's own email domain (alex@acme.com ⇒ @acme.com)
  - POST /api/admin/users rejects (422) any invite that doesn't match
    the derived domain
  - New GET /api/admin/config exposes the domain to the UI
  - /admin Add-member dialog splits the email field into a handle
    input + a locked @domain suffix when a domain is enforced
  - .env.example documents INVITE_EMAIL_DOMAIN and the super-admin
    bootstrap rules (demo creds + first-account-becomes-super-admin)

Verification
  - scripts/lockdown-test.mjs covers: /signup disabled screen,
    /api/signup 403, /login link removal, wrong-domain rejection,
    correct-domain invite success, /api/admin/config domain exposure
  - All functional checks pass (the only red is a known Playwright
    CSS-on-demand dev-server race, not a real bug)
